# 테스트 계획 초안

이 문서는 검증 전략의 기준이다. 테스트 코드는 아직 없으며 아래는 향후 구현 허용 시의 계획이다. 명령의 실제 구성·실행 상태는 [README](../README.md)를 따른다. 목표 수치의 원문 근거는 [개요](project-brief.md)와 제안서 §3.1이다.

## 현재 P2 문서 검사
범위는 파일 존재, 상대 링크 대상, 제안서·Q1~Q5·ADR 일치, 개인/AI 역할과 수정 제한, 금지 작업·명령 상태 표기의 일관성이다. 앱 실행·Ruff·pytest와 네트워크 검증은 미구성·미실행이다.
결과는 날짜·대상·방법·실제 결과·미검사·추가 수정 횟수를 기록한다. 현재 P2 검사 결과는 아래 검사 기록에 남긴다.

## 향후 테스트 대상·전략
| 대상 | 확인할 행동 | 전략·근거 |
|---|---|---|
| PDF 처리·출처 | 3개 이상 텍스트 PDF 처리, 페이지·문서 ID 보존, 빈/손상/스캔 PDF 안내 | 직접 만든 비민감 PDF에 정답 페이지 마련, 추출·청크 경계 검증. §3.1~§3.2 |

| 라우팅·상태 | QA·요약·비교 경로, 재검색 최대 한 번, 근거 부족 안내 | 모델 응답을 고정한 단위·경로 검사. §3.1~§3.2 |
| 질의응답 | 답변 내용과 문서명·페이지가 실제 근거에 맞음 | 정답·허용 근거 페이지와 대조, 근거 없는 질문 포함. §2.2·§3.3 |
| 요약 | 핵심 내용·키워드, 문서 밖 단정 억제 | 정답 핵심 항목과 근거 수동 평가. §3.3 |

| UI·오류 | 선택·질문·결과·근거 표시, 잘못된 입력 안내 | 앱 구현 이후 로컬 수동 흐름 확인. §3.3 |
| 데이터·비용 | 키·본문 로그 누출 방지, 허용 샘플만 사용, 외부 호출 보류 | 로컬 대체 클라이언트로 기본 테스트, 네트워크 사용은 명시적으로 분리. ADR-0002~0005 |

초기 자동 검증은 외부 호출 없이 수행하는 것을 제안한다. 유료 호출 0원 정책 하에서는 실제 OpenAI 연동 검증을 실행하지 않는다. 실서비스 검증은 개인의 연결·비용 결정과 당시 공식 요금·데이터 정책 확인 후 별도 작업으로 한다. 대체 응답 검증은 실제 모델의 품질·API 호환성을 보증하지 않는다.

## 평가 설계 초안
제안서의 목표는 질문 30개 이상, 근거 기반 답변의 문서명·페이지 표시율 90% 이상, 정상 입력 기능 성공률 90% 이상이다. 현재 달성 결과가 아니다.
평가 질문에는 문서 ID, 작업 유형, 질문, 기대 핵심 내용, 허용 근거 페이지, 근거 부족 여부를 기록할 예정이다. 근거 표시율과 근거 적합성은 분리해 채점한다.
제안하는 계산은 ‘표시 대상 답변 중 문서명·페이지가 모두 있는 답변 비율’, ‘사전 정의한 정상 입력 중 기대 작업·출력 형식을 수행한 비율’이다. 정상 입력 정의, 유형별 문항 배분, 내용 정확성/적합성 기준은 아직 확정되지 않았다. 평가 실행 전에 개인과 확정한다.
결과 기록에는 날짜, 버전 식별자(가능할 때), 샘플 식별자·권리, 설정, 총수·제외·분모·성공/실패, 오류 원인, 평가자를 남긴다. 비민감 결과만 보관하며 키·개인정보·실제 문서 본문은 넣지 않는다.

## 실패 처리
[workflow](workflow.md)의 최초 검사 후 추가 수정 최대 2회를 따른다. 계속 실패하면 원인·시도·다음 조치를 기록하고 중단한다. 미실행은 실패·성공과 구분한다.

- 대상: P2 하네스 문서와 기존 P1 문서.
